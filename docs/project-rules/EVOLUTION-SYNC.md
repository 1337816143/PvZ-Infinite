# PvZ-Infinite → 个人进化网站同步规则

本文件定义 `1337816143/PvZ-Infinite` 与个人进化网站 `1337816143/My-Evolution` 的长期同步关系。

## 1. 同步目标

- 游戏专业上游：`1337816143/PvZ-Infinite`。
- 个人进化网站唯一维护源：`1337816143/My-Evolution`。
- 公开镜像：`1337816143/Evolution`，只允许由 `My-Evolution` 的标准发布流程自动生成，禁止直接维护。
- 网站目标模块：**AI 3D 创作与游戏开发实验室**，公开页面 `pages/ai-3d-lab.html`。

本游戏项目不是一次性比赛条目。后续主设计、技术原型、Android 实验、3D/视觉资产和真实测试进展都应在适合公开的前提下持续同步到该实验室模块。

## 2. 必须触发同步的更新

出现下列任一实质变化，本轮项目完成前必须检查是否需要同步个人进化网站：

1. Master GDD 的已确认设计边界、设计支柱或系统状态发生变化；
2. Concept / Prototype / Lab 版本发生实质升级；
3. 新增可玩的原型、Android APK、TapPlay、真机、性能或稳定性验证结果；
4. 新增可公开的游戏截图、视频、概念图、GLB/GLTF 模型、动画或其他素材；
5. 引擎、工具链、AI 3D 工作流、Blender/Godot/Unity/Unreal 等技术路线发生变化；
6. 正式名称、原创化/IP 边界、平台与发行方向发生变化；
7. 聚光灯等比赛的报名、日志、试玩、审核、投稿状态有可验证的新证据；
8. 项目 Pages、公开演示或仓库入口发生变化；
9. 项目从“概念”进入“原型/开发/测试/发行”等新阶段。

纯拼写修复、内部格式整理、无公开意义的微小重排可不单独触发网站更新。

## 3. 网站应该同步什么

优先同步以下公开信息：

- 当前项目名与候选名；
- 当前阶段和最新版本；
- 一句话定位与核心玩法摘要；
- 最新已确认的设计边界；
- 当前原型/技术验证状态；
- 真实通过、失败、未验证的测试证据；
- 可公开截图、视频、模型与演示入口；
- PvZ-Infinite 仓库、Pages、Master GDD 或公开文档入口；
- 比赛目标与赛期状态（若仍相关）；
- 下一阶段的公开目标。

同步到网站的内容必须是**公开摘要和可公开证据**，不是把整个专业仓库复制到网站。

## 4. 禁止公开的内容

除非用户明确要求公开，否则不得把以下内容同步到个人进化网站：

- 完整原始聊天记录；
- 私人账号、报名身份资料、Cookie、Token、密钥和签名文件；
- 未审核的私人照片、个人资料或设备信息；
- 未获得许可的第三方资产；
- 仍使用受保护 IP 的具体美术、音乐、角色素材；
- 仅有 AI 口头判断、没有证据的“已完成/已通过”状态。

`PvZ Infinite / 植物大战僵尸：无限` 仍应在公开页面中标为内部代号或历史构思名，直到原创正式名称确定。

## 5. 同步映射

| PvZ-Infinite 事实源 | My-Evolution 目标 |
|---|---|
| `docs/design/00-master-game-concept.md` | AI 3D 实验室的项目设计摘要/状态 |
| `README.md`、`CHANGELOG.md` | 当前阶段、版本、入口和重要变化 |
| `android-lab/` 及真实测试证据 | `site/data/ai3d-game-goal.json` 中与比赛/Android验证相关的状态 |
| 可公开截图、视频、3D资产 | AI 3D 实验室项目展示区/后续素材区 |
| GitHub Pages / 项目公开入口 | AI 3D 实验室中的“查看项目/查看设计”链接 |
| 完整对话与内部纪要 | **不直接公开**；只提炼用户已确认的公开摘要 |

## 6. 标准同步流程

1. 先完成 PvZ-Infinite 本轮设计/开发更新并取得真实证据；
2. 判断哪些内容适合公开；
3. 读取 `My-Evolution/AGENTS.md`、`00-system/AI-MAINTENANCE-RULES.md` 和 `08-ai-digital-systems/ai-3d-lab/SYNC.md`；
4. 只修改 `My-Evolution`，不得直接编辑 `Evolution`；
5. 更新 AI 3D 实验室对应公开源；
6. 运行/等待 `npm ci && npm test` 全部通过；
7. 通过私有仓库 PR 或合规主分支提交；
8. 等待 `publish.yml` 生成私有快照并镜像到公开仓库；
9. 核对公开 Pages 与本次真实版本/证据一致。

## 7. 自动化边界

当前规则表示“**每次实质更新必须同步检查并执行**”，不等于已经建立跨仓库实时 webhook。没有真实自动化证据时，不得声称两个仓库会自动实时互相同步。

后续若建立 GitHub Actions / webhook 自动同步，只允许同步明确公开、结构化的项目摘要和证据，不允许把整个 PvZ-Infinite 仓库或原始聊天自动公开。

## 8. 项目完成定义补充

对满足第2节触发条件的迭代，在最终回复中必须说明：

- 本轮是否触发个人进化网站同步；
- `My-Evolution` 更新了哪些文件/PR；
- CI/发布是否已经通过；
- 如果尚未上线，明确标注“已提交待验证/待发布”，不得写成“已同步上线”。
