# 设计决策登记表

本文件只登记已经形成明确方向的决策；待讨论内容不写成确定结论。原始理由见 `docs/conversations/`。

## D-001：美国农场场景基线

状态：已接受，仍可扩展生物群系。  
结论：首个核心区域采用虚构的美国中西部—大平原过渡县；农舍靠近县道，生产建筑位于侧后方，周围为农田、牧场、防风林和农业设施。多人采用同路邻居、十字路口合作聚落或家族农场，而不是纯城市住宅街区。

## D-002：3D与镜头

状态：已接受。  
结论：完整3D场景与单位；主操作使用可旋转、可缩放的斜俯视策略镜头，呈现2.5D式清晰度。首版不扩张为完整第三人称射击游戏。

## D-003：昼夜循环

状态：已接受。  
结论：采用清晨收获与侦察、白天经营建设、黄昏预警、夜间袭击、Boss/事件高潮、黎明结算的农业日结构。白天承担大量局外成长，但世界保持连续。

## D-004：黎明结算与持久资产

状态：已修订并接受。  
旧方案：每晚重置卡牌、植物变异、临时炮塔和天气。  
当前结论：只重置肉鸽卡牌、短期天气、临时命令和当夜规则；存活植物、持久变异、炮塔、设施和长期天气跨夜保留。角色死亡和设施摧毁制造损失。

## D-005：长期平衡方式

状态：方向已接受，具体数值待验证。  
结论：不使用机械清零作为主要平衡工具；采用土地与系统承载能力、维护成本、变异稳定度、真实战损、世界威胁响应、阵容反克制和高成本不完整恢复。

## D-006：玩家存在方式

状态：已接受。  
结论：轻量策略指挥与自由主体同时存在。植物、炮塔、宠物和基础机器人自动工作；玩家角色自由移动、自动攻击、点击交互、会死亡；复杂指挥集中在大型无人农机、车队、无人机和机甲，并使用区域级简化命令。

## D-007：角色死亡与复生

状态：方向已接受，名称暂定。  
结论：采用受 Operation Phoenix 启发但原创化的“火种计划”。意识备份写入新身体；原尸体、装备和背包留在死亡地点；复生消耗时间、电力、生物材料和培养体，连续死亡产生身体不稳定。

## D-008：风险系统名称

状态：建议采用，仍可更名。  
结论：原“风险契约”优先称为“风险委托”，表示玩家主动增加困难以换取奖励的可选任务。

## D-009：模式边界

状态：总体方向已接受。  
结论：单机家园、邻居合作和自由PvPvE共享长期档案，但永久家园不因一次匹配被整体删除；合作迁入不复制原建筑；自由模式使用带入额度、战地基地、撤离容量和战备评级。

## D-010：离线保护

状态：总体方向已接受，商业化规则待细化。  
结论：所有成员离线后启用无限低能保护；高能模式消耗储能并离散结算防御、耐久和有上限的收益；能量耗尽后自动降级。

## D-011：被否定方案必须回写对应章节

- 状态：已确认
- 结论：弃用方案除保留在原始问答和变更日志外，还必须出现在相关系统章节，并标注“弃用想法”或“弃用名称”。
- 原因：让读者在查看当前设计时即可理解替代关系，避免旧想法被误认为遗漏或未来重新提出。

## D-012：新增名称候选“农场：无限”

- 状态：候选，未定名
- 结论：保留PvZ Infinite作为内部代号，同时把“农场：无限 / Farm: Infinite”列为原创名称候选。
- 原因：更贴合永久农场和无限成长，也有利于未来脱离既有IP。

## D-013：建立单文件无损HTML档案

- 状态：已确认
- 结论：仓库持续生成 `PvZ-Infinite-Archive.html`，完整嵌入除自身外的所有仓库文件，并提供校验、阅读、搜索、原文和本地编辑导出能力。
- 原因：降低文档分散带来的查看成本，同时不替代原文件和Git历史。



## D-014：植物个体差异

- 状态：已确认
- 结论：同种植物具有受控的自然形态差异，默认只改变外观；明确的生长品质和基因词条才改变数值。

## D-015：永久与临时变异分层

- 状态：已确认
- 结论：永久变异进入基因库并可高成本DIY、复刻和授权；临时变异混入普通肉鸽卡牌选择，在进入白天时失效，除非明确触发基因固化。

## D-016：独立移动植物与编队

- 状态：已确认，数量待原型验证
- 结论：移动战斗型特定变异植物可成为独立个体。当前验证上限为1名角色加4株植物；默认跟随角色，接管植物后角色和其他植物跟随当前植物锚点。

## D-017：多视角目标

- 状态：方向已确认，分阶段实现
- 结论：人物、载具、机甲和适配植物以第一人称、第三人称和上帝视角为最终目标；原型优先上帝视角和第三人称。

## D-018：阶段化交易系统

- 状态：已确认进入设计，经济参数待验证
- 结论：先做邻居交换，再做区域市场，后做基因模板、繁育许可和谱系授权。所有高价值交易需要来源追踪、托管和反复制。

## D-019：AI接手与Pages规则
