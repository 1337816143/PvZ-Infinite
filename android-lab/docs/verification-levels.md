# 验证分层与暂缓真机时的推进范围

更新：2026-09-05。适用范围：android-lab 赛前技术验证，不是正式参赛游戏。

## 用户当前安排

用户明确表示暂时没有时间验证手机，要求继续推进。手机操作不是当前所有工程工作的前置阻塞。可以推进源码、自动化、桌面渲染、模拟器、构建及证据整理；不能把未执行的真机或 TapPlay 验收改为通过，也不重复催促用户立即操作。

## 六个独立状态

| 层级 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 源码与数学测试 | 解析、投影反算、碰撞、存档校验等已覆盖条件下通过 | 渲染、触控、安卓启动 |
| 桌面实际引擎运行 | 引擎渲染、合成指针路由、指定画面 | 安卓驱动、物理手势、TapPlay |
| Android 模拟器 | 实际 Android 系统内安装、启动、adb 注入操作、应用生命周期、沙盒文件 | ARM 真机驱动与性能、物理多指触摸、TapPlay |
| 真实安卓手机 | 指定设备上的启动、手感、安全区、发热和稳定性 | 其他设备、TapPlay 沙盒 |
| TapPlay | 通过平台入口的实际启动、保存恢复及检测状态 | 自动获得活动投稿或奖项资格 |
| 投稿 | 有效投稿回执和参赛页面状态 | 任何尚未完成的过程条件 |

模拟器输出独立包 `io.github.u1337816143.farmlab.emulator`，仅含 x86_64；手机包仍为原实验包名，含 ARMv7 和 ARM64。两者共用同一提交的玩法无关实验源码，但架构与窗口选项不同，不能声称测过模拟器就已测过 ARM 手机包。

## v0.2.0 验证范围

- 主存档使用带 SHA-256 的数据封装，检测意外损坏；校验值不是防作弊认证。
- 写入同目录临时文件、复读验证、保留上一份可读主存档为备份，再进行重命名提交。
- 不把损坏主文件复制覆盖已知可读的备份；相同状态不轮换备份。
- 读取顺序：主文件、备份、遗留临时文件；在独立对象验证后再恢复运行中状态。
- 保留 v0.1.0 旧实验存档兼容，不等于不同签名安装包可以覆盖安装。
- 重启自动恢复；操作后及周期性保存；暂停时保存并清理移动路线、方向键和指针。
- 测试取消触摸、抬手跨入工具栏、按钮拖出和双指手势误放置。
- 通过调试安装内部诊断文件观察真实 Android 程序状态，仅在应用私有目录显式存在 `ci_probe.enabled` 时开启；无联网或远程控制接口。

不承诺操作系统断电或磁盘损坏时绝不丢数据。没有通过压力测试前不使用“永不丢档”“全机型兼容”等表述。
